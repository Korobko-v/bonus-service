## 📋 О проекте

REST-сервис для управления бонусными картами клиентов с поддержкой транзакций, баланса и истории операций.

## 🚀 Функциональность

### Основные возможности:
1. **Начисление бонусов** по карте клиента
2. **Списание бонусов** по карте клиента
3. **Возврат бонусов** (например, при возврате товара)
4. **Получение баланса** по номеру карты
5. **Получение истории операций** по номеру карты

### Ролевая модель:
- **ADMIN**: Полный доступ ко всем операциям
- **USER**: Доступ только к своим данным (баланс и история своих карт)

## 🏗️ Архитектура

### Технологический стек:
- **Java 17+** с Spring Boot 3.x
- **PostgreSQL** - основная база данных
- **Liquibase** - управление миграциями
- **Spring Security** - аутентификация и авторизация
- **JWT** - токены для безопасного доступа
- **Docker** - контейнеризация

### Структура базы данных:
- `bonus_cards` - информация о бонусных картах
- `bonus_transactions` - история транзакций по картам

## 📊 Этапы разработки

### Этап 1: Базовая реализация
Создана структура проекта и реализованы основные REST-эндпоинты:
- `POST /api/v1/bonus/accrue` - начисление бонусов
- `POST /api/v1/bonus/write-off` - списание бонусов
- `POST /api/v1/bonus/refund` - возврат бонусов
- `GET /api/v1/bonus/balance/{cardNumber}` - получение баланса
- `GET /api/v1/bonus/history/{cardNumber}` - получение истории операций

### Этап 2: Миграции (Liquibase)
Реализованы миграции для таблиц:
- `bonus_cards` - хранение информации о картах
- `bonus_transactions` - хранение истории транзакций

### Этап 3: Безопасность (Spring Security)
Подключён модуль Spring Security с поддержкой:
- JWT-аутентификации
- Ролевой авторизации (ADMIN/USER)
- Разделение доступа к данным:
    - Администраторы: доступ ко всем операциям
    - Пользователи: доступ только к своим данным

### Этап 4: Оптимизация производительности
В тестовую базу загружены:
- 100,000 бонусных карт
- 1,000,000 транзакций

#### Добавленные индексы для оптимизации:

| Таблица | Индекс | Назначение |
|---------|---------|------------|
| `bonus_cards` | `idx_bonus_cards_card_number` | Ускорение поиска по номеру карты |
| `bonus_cards` | `idx_bonus_cards_client_id` | Ускорение поиска по владельцу |
| `bonus_cards` | `idx_bonus_cards_card_number_client_id` | Составной индекс для проверки доступа |
| `bonus_transactions` | `idx_bonus_transactions_card_id` | Ускорение JOIN с картами |
| `bonus_transactions` | `idx_bonus_transactions_created_at` | Ускорение сортировки по дате |
| `bonus_transactions` | `idx_bonus_transactions_order_id` | Идемпотентность транзакций |
| `bonus_transactions` | `idx_bonus_transactions_card_id_amount` | Ускорение поиска транзакции по сумме и карте |

Анализ производительности запросов до и после добавления индексов представлен в файле `explain_analyze.txt`.

### Этап 5: Контейнеризация и тестирование
- **Dockerfile** для контейнеризации приложения
- **docker-compose.yml** для запуска всего стека
- **Покрытие тестами** всех компонентов системы

## 🔧 API Endpoints

### Административные операции (требуют роли ADMIN):
- `POST /api/v1/bonus/admin/card` - создание новой карты
- `POST /api/v1/bonus/accrue` - начисление бонусов
- `POST /api/v1/bonus/write-off` - списание бонусов
- `POST /api/v1/bonus/refund` - возврат бонусов
- `GET /api/v1/bonus/balance/admin/{cardNumber}` - баланс любой карты
- `GET /api/v1/bonus/history/admin/{cardNumber}` - история любой карты
- `PATCH /api/v1/bonus/admin/card/{id}/deactivate` - деактивация карты

### Пользовательские операции (доступны USER и ADMIN):
- `GET /api/v1/bonus/balance/{cardNumber}` - баланс своей карты
- `GET /api/v1/bonus/my-history/{cardNumber}` - история своей карты
